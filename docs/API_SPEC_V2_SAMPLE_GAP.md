# 기존 샘플과 최종 백엔드 v2 차이 및 반영 결과

- 점검 기준일: 2026-08-21
- 최종 계약: [`API_SPEC_V2_DRAFT.md`](./API_SPEC_V2_DRAFT.md)
- 구현 위치: `hearo_backend/`, `dashboard_api_v2.py`, `infra/`, `tests/`

## 결론

과거 샘플과 확정 요구사항 사이의 소스 코드 차이는 반영되었습니다. 남은 일은 AWS 최종 테이블 생성, EC2의 8001 병렬 배포, MQTT 수집기 연결, 실제 프론트 연동과 물리 기기 통합 테스트입니다. 현재 EC2에서 실행 중인 예전 `/v2` 프로세스가 자동으로 새 코드가 된 것은 아니므로 배포 절차를 별도로 수행해야 합니다.

## 반영 상태

| 영역 | 과거 샘플 | 최종 구현 | 상태 |
|---|---|---|---|
| 로그인 | 이메일 | 별도 `login_id` | 완료 |
| 회원가입 | 이메일·이름·비밀번호 | 아이디·이름·휴대폰·비밀번호·동의 | 완료 |
| 신규 가구 | 주소 없음 또는 선택 | 검증된 긴급 주소 필수 | 완료 |
| 가족 가입 | 가입 중 즉시 연동 | 미연동 가입 후 코드 입력 또는 나중에 연동 | 완료 |
| 초대 코드 | 일회용 8자리 | 재발급 전까지 여러 명이 쓰는 6자리, 24시간 | 완료 |
| 가구 미리보기 | 없음 | 주소를 제외한 이름·인원·등록일 | 완료 |
| 이름 편집 | 실제 이름 변경 가능성 | 사용자별 표시 이름(alias) | 완료 |
| 연동 해제 | owner가 타인을 삭제 | 본인만 해제, owner면 가구 비활성화 | 완료 |
| 주소 보호 | 일반 응답 노출 가능성 | 전용 API, owner 수정/member 조회 | 완료 |
| 알림 이력 | 7일 | KST 최근 30일과 빈 날짜 | 완료 |
| 알림 상세 | 없음 | 가구 범위 특정 알림 1건 | 완료 |
| 기기 설정 | 연결·LED·민감도 | 연결·LED만 | 완료 |
| 진동·녹음 | capability 또는 향후 고려 | API 범위에서 제거 | 완료 |
| 오류 형식 | 엔드포인트별 상이 | code/message/field_errors/request_id | 완료 |
| DynamoDB | 이메일 기반 샘플 레코드 | login·phone alias와 최종 가구 모델 | 소스 완료, 새 테이블 배포 필요 |

## 의도적으로 구현하지 않은 기능

- 로그인하지 못한 사용자의 비밀번호 찾기: SMS 본인 인증 정책이 확정되지 않음
- 107 연결: 웹앱 직접 연결 수단이 없어 프론트 범위에서 제거
- 녹음 저장·재생 및 알림 피드백 저장
- 진동 알림과 민감도 조절
- 세탁 완료 등 이번 분류 범위 밖 알림
- 실제 112/119 신고 대행 서버: 프론트의 `tel:` 동작 사용

## 배포에서 아직 해야 할 일

1. 현재 실행 중인 v1과 과거 v2를 백업합니다.
2. 과거 이메일 기반 core 테이블과 분리된 최종 DynamoDB 테이블을 만듭니다.
3. 최종 소스를 EC2 `/opt/hearo-backend-v2-r2`에 반영하고 테스트합니다.
4. 8001 systemd 서비스를 새 코드로 재시작합니다.
5. Nginx `/v2/` 경로에서 health와 OpenAPI를 확인합니다.
6. MQTT bridge의 내부 API 주소를 8001로 바꾸고 알림 저장을 확인합니다.
7. 프론트 smoke test 후 base URL을 `/v2`로 전환합니다.

구체적인 명령과 성공·되돌리기 기준은 [`DEPLOYMENT.md`](./DEPLOYMENT.md)에 있습니다.
