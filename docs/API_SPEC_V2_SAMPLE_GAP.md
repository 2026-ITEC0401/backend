# 기존 샘플과 백엔드 v2.4.0 차이 및 반영 상태

- 점검 기준일: 2026-10-07
- 최종 계약: [`API_SPEC_V2_DRAFT.md`](./API_SPEC_V2_DRAFT.md)
- 개인정보 보관·동의 계약: [`PRIVACY_RETENTION_V2_4.md`](./PRIVACY_RETENTION_V2_4.md)
- 구현 위치: `hearo_backend/`, `dashboard_api_v2.py`, `infra/`, `scripts/`, `tests/`

## 결론

과거 샘플과 확정 요구사항 사이의 소스 차이는 v2.4.0 기준으로 반영되었습니다. 이번 버전은 기존 전체 API에 알림 90일 보관·조회 제한과 문서 버전별 동의 API를 추가하며, 최근 7일 이력·미확인 화면 범위는 유지합니다.

실제 GitHub 반영 여부는 대상 커밋과 브랜치, 운영 반영 여부는 외부 `/v2/health`의 `2.4.0`과 새 API 검증 결과로 각각 확인합니다. 로컬 파일이나 테스트 통과만으로 GitHub·EC2 반영 완료를 뜻하지 않습니다. 키트 등록·가구 귀속 API는 v2.4.0에 구현되지 않았으며 현재 API 목록에 포함하지 않습니다.

## 반영 상태

| 영역 | 과거 샘플 | v2.4.0 최종 구현 | 상태 |
|---|---|---|---|
| 로그인 | 이메일 | 별도 `login_id` | 완료 |
| 회원가입 | 이메일·이름·비밀번호 | 아이디·이름·휴대폰·필수 동의값과 선택 버전 | 완료 |
| 공개 사용자 | 동의 버전 없음 | `terms_version`, `privacy_version`, `consented_at` 포함 | 완료 |
| 문서 정책 | 고정 문구 또는 버전 없음 | `GET /legal/policies`로 버전·URL·시행·필수 여부 조회 | 완료 |
| 본인 동의 | 최신 여부 확인·재동의 API 없음 | `GET/PATCH /me/consents`, 버전별 영수증과 오염 레코드 복구 | 완료 |
| 기존 회원 호환 | 일괄 최신 동의 처리 가능성 | 확인되지 않은 버전은 `null`, `required=false`이면 기존 가입 요청 허용 | 완료 |
| 신규 가구 | 주소 없음 또는 선택 | 주소 생략 후 owner 온보딩을 권장하되, 기존 프론트의 가입 중 선택 주소도 계속 허용 | 완료 |
| 가족 가입 | 가입 중 즉시 연동 | 미연동 가입 후 코드 입력 또는 나중에 연동 | 완료 |
| 초대 코드 | 일회용 8자리 | 재발급 전까지 여러 명이 쓰는 6자리, 24시간 | 완료 |
| 가구 미리보기 | 없음 | 주소를 제외한 이름·인원·등록일 | 완료 |
| 이름 편집 | 실제 이름 변경 가능성 | 사용자별 표시 이름 alias | 완료 |
| 연동 해제 | owner가 타인을 삭제 | 본인만 해제, owner면 가구 비활성화 | 완료 |
| 실시간 권한 회수 | REST 권한 변경 후 기존 WS가 남을 수 있음 | 연동 해제·탈퇴·비밀번호 변경 후 WS 종료, 연결 등록 전후 권한 재검증 | 완료 |
| 주소 보호 | 일반 응답 노출 가능성 | 전용 API, owner 수정·member 조회, 행안부 프록시 | 완료 |
| 알림 이력 | 최근 7일 | KST 최근 7일과 빈 날짜 유지 | 완료 |
| 알림 보관·조회 | 별도 만료 없음 | 발생 후 90일 전까지만 목록·latest·detail·미확인에 노출 | 소스 완료, 운영 TTL·정리 적용 필요 |
| 알림 저장 | 본문 중심 | 본문과 `ALERTID` 별칭에 동일 TTL, 만료 재수집 저장·WS 미발행 | 완료 |
| 하이브리드 알림 | source·publisher·capture 구분 불명확 | hub 발행자 검증, 실제 capture 기준 source·location 저장 | 완료 |
| 알림 상세 | 없음 | 가구 범위 특정 알림 1건, 90일 만료 후 `404` | 완료 |
| 기기 설정 | 연결·LED·민감도 | 연결·LED만, LED 변경과 오디오 전송 분리 | 완료 |
| 진동·녹음 | capability 또는 향후 고려 | API 범위에서 제거 | 완료 |
| 회원 탈퇴 | 계정 식별정보 중심 | 동의 영수증·미확인·참조정보 정리, 연결 해제와 최종 삭제의 비원자성 명시 | 완료, 운영 복구 절차 필요 |
| 오류 형식 | 엔드포인트별 상이 | `code`, `message`, `field_errors`, `request_id` | 완료 |
| DynamoDB | 이메일 기반 샘플 레코드 | login·phone alias, 최종 가구 모델, 알림 TTL과 동의 영수증 | 소스 완료, v2.4 운영 절차 필요 |

## 의도적으로 구현하지 않은 기능

- 키트 등록·가구 귀속 claim API
- 로그인하지 못한 사용자의 비밀번호 찾기
- 107 연결
- 녹음 저장·재생 및 알림 피드백 저장
- 진동 알림과 민감도 조절
- 세탁 완료 등 이번 분류 범위 밖 알림
- 실제 112·119 신고 대행 서버
- 재동의 필요 계정의 로그인·기기·MQTT·회원 탈퇴 전역 차단
- 기존 회원에게 현재 문서 버전을 일괄 배정하는 마이그레이션

## GitHub와 운영 반영에서 확인할 일

1. 검증한 v2.4.0 커밋과 API 명세가 같은 브랜치에 포함됐는지 확인합니다.
2. 새 r6 스테이징과 별도 테스트 테이블에서 전체 테스트, `/health`, `/legal/policies`, OpenAPI와 실제 프론트 흐름을 확인합니다.
3. 실제 문서 버전·시행 시각·공개 URL이 확정되기 전에는 다섯 문서 환경값을 비우고 `HEARO_LEGAL_CONSENT_REQUIRED=false`를 유지합니다.
4. 신규 가입, 기존 미버전 회원, 부분·오염 동의 복구와 기존 로그인·기기·LED·MQTT·탈퇴 회귀를 확인합니다.
5. 90일 조회 차단을 먼저 배포한 뒤 운영 알림 마이그레이션 계획을 검토하고 TTL과 시간당 정리를 적용합니다.
6. 연결된 계정 탈퇴의 최종 삭제 실패 시 `/me`와 `/households/current` 재조회, owner 가구 복구를 위한 관리자 절차를 준비합니다.
7. 외부 `/v2/health`가 `2.4.0`이고 실제 새 API와 프론트 smoke test가 통과한 뒤에만 운영 반영 완료로 기록합니다.

구체적인 명령, 중단 기준과 롤백 주의사항은 [`DEPLOYMENT_V2_4.md`](./DEPLOYMENT_V2_4.md)를 따릅니다.
